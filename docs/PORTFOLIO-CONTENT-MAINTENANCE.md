# Portfolio Content and SEO Maintenance Guide

Use this checklist when publishing a new project, updating a case study or changing public portfolio metadata.

## Project case study quality

- [ ] State the intended audience and the problem the project addresses.
- [ ] Separate shipped capabilities from planned or experimental features.
- [ ] Describe the user's role and the technical contribution accurately.
- [ ] Include a working demo or repository link only when it is publicly accessible.
- [ ] Avoid publishing customer names, screenshots, credentials or personal data without permission.
- [ ] Add a concise outcome supported by evidence; do not invent adoption, revenue or performance metrics.

## Page metadata

For each important page, review:

- A unique, descriptive page title that identifies the subject.
- A concise meta description that accurately summarises the page.
- A canonical URL that points to the preferred public URL.
- Open Graph title, description and image for social sharing.
- A meaningful language declaration and mobile viewport.
- Descriptive image alt text; decorative images should not create noisy descriptions.

## Technical discoverability

- [ ] Confirm important pages are reachable through ordinary links.
- [ ] Check for broken internal links and missing assets.
- [ ] Ensure robots directives do not accidentally block public portfolio pages.
- [ ] Keep sitemap entries aligned with canonical, indexable URLs.
- [ ] Use structured data only when its properties match visible page content.
- [ ] Avoid creating thin duplicate pages for keyword variations.

## Performance and accessibility

- [ ] Test at narrow mobile widths and desktop widths.
- [ ] Verify keyboard navigation and visible focus indicators.
- [ ] Respect reduced-motion preferences.
- [ ] Provide intrinsic image dimensions or an aspect ratio to reduce layout shifts.
- [ ] Compress large images and avoid loading below-the-fold media eagerly when unnecessary.
- [ ] Check contrast and ensure information is not conveyed by colour alone.

## Measurement and verification

1. Record the URL and date of each significant content change.
2. Inspect the deployed page, not only the local source.
3. Check browser console errors and network failures.
4. Use Search Console to review indexing and search performance over a suitable period.
5. Compare like-for-like date ranges and annotate major content or deployment changes.
6. Treat ranking and traffic changes as observations, not proof that one edit caused them.

## Safe publishing rule

A portfolio claim should be demonstrable from a live product, source code, documented test or clearly labelled prototype. Accuracy and trust matter more than keyword repetition.
